# PR-12 — Полное покрытие Validation Bench data-testid

## Цель
Все интерактивные элементы Validation Bench получают ровно один
`data-testid`; все Playwright-тесты панели используют
`page.getByTestId(...)` как основной способ поиска элементов, вместо
`locator("#id")` / `getByText(...)`.

## Что сделано
1. Добавлены `data-testid` для всех интерактивных элементов
   `App.ts` и `SessionPanel.ts` (57 значений) — полный перечень в
   docs/TEST_IDS.md.
2. Во всех Playwright-тестах (`smoke.spec.ts`, `automatic.spec.ts`,
   `interactive.spec.ts`, `report.spec.ts`, `scenario-source.spec.ts`,
   `utils/helpers.ts`) все `page.locator("#...")` заменены на
   `page.getByTestId(...)`.
3. Поиск по `tests/playwright` подтверждает: `locator("#...")`
   встречается один раз — `#app` (задокументированное исключение,
   инфраструктурный корень монтирования, не элемент Bench).
4. `getByText(...)` остался только внутри `getByTestId("verification-panel").getByText(/PASS|FAIL/)`
   — это не поиск элемента по тексту, а ожидание значения результата
   внутри уже найденного по testid блока (у PASS/FAIL нет отдельных
   элементов/testid'ов).
5. `docs/TEST_IDS.md` — новый файл, контракт тестовой панели.

## Отклонения от примера именования в ТЗ
Пример в ТЗ был ориентировочным (`interactive-start-button`,
`manual-result-pass/fail/skip` и т.п.) и не совпадает 1:1 с реальными
элементами UI:

- **`interactive-start-button`** не создан: в текущей реализации
  Interactive-сессия стартует автоматически при выборе
  `validation-mode = interactive`, отдельной кнопки старта нет.
- **`manual-result-pass/fail/skip`** заменены на реальную модель
  панели — два независимых вопроса ("Recognized correctly?",
  "Expected speech heard?") плюс "Skip Step", а не единый вердикт
  pass/fail/skip. Использованы `manual-recognized-yes/no-button`,
  `manual-heard-yes/no-button`, `interactive-skip-button`.
- **`report-preview`** и **`last-report`** в ТЗ перечислены как разные
  блоки; в реализации это один и тот же элемент — оставлен
  `last-report`, так как это уже устоявшийся контракт (используется в
  `automatic.spec.ts`, `report.spec.ts`, `smoke.spec.ts` до PR-12).
- **`interactive-stop-button`** сопоставлен с кнопкой "Pause"
  (ближайший по смыслу аналог — останавливает прогресс сессии).
  Добавлен также `interactive-resume-button` (для "Resume"), которого
  не было в примере ТЗ, но элемент существует в UI и должен иметь testid.

Список всех решений — в docs/TEST_IDS.md, там же таблица «Legacy» и
«Документированные исключения».

## Проверка

- Синтаксическая проверка изменённых `*.spec.ts` / `helpers.ts` —
