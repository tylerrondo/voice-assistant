# Сценарий SC-010: Одновременная работа с несколькими заказами (Multi-Context Lifecycle)

## 1. Цель
Доказать предметную способность водителя одновременно управлять пулом из 3–4 независимых Dialogue Contexts:
- **1001:** Завершение с оплатой `card`.
- **1002:** Отмена `CANCELLED` с гарантированным `executionCount === 0`.
- **1003:** Завершение с оплатой `cash`.
- **1004:** Восстановление после ошибочной реплики и успешное завершение `cash`.

## 2. Матрица переходов жизненного цикла
| Context / Order | Действие / Голосовая команда | Итоговый статус | Итоговый Execution |
|---|---|---|---|
| **1001** | «Заказ 1001» $\to$ «Картой» | `COMPLETED` | `{ orderId: 1001, payment: 'card' }` (1 execution) |
| **1002** | «Заказ 1002» $\to$ «Отмена» | `CANCELLED` | `0 executions` |
| **1003** | «Заказ 1003» $\to$ «Наличными» | `COMPLETED` | `{ orderId: 1003, payment: 'cash' }` (1 execution) |
| **1004** | «Прими заказ 1004» $\to$ «Не знаю» $\to$ «Наличными» | `COMPLETED` | `{ orderId: 1004, payment: 'cash' }` (1 execution) |

## 3. Архитектурные инварианты
1. Каждый контекст имеет независимый `contextId`.
2. Завершение или отмена одного контекста не изменяет состояние и слоты других.
3. Попытка подать реплику после `CANCELLED` (например, «Заказ 1002» $\to$ «Наличными») не воскрешает заказ (`0 executions`).
4. Перекрёстное смешивание (1001+cash, 1002+card, 1003+card) строго равно **0 выполнений**.
