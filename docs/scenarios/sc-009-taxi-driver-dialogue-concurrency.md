# Сценарий SC-009: Аудит параллельности контекстов диалога водителя такси

## 1. Цель
Определить и экспериментально доказать поведение системы при попытке создания двух параллельных незавершённых диалогов:
1. Заказ 1001 $\to$ неполный `WAITING_FOR_SLOT(payment)`.
2. Заказ 1002 $\to$ новый Intent `WAITING_FOR_SLOT(payment)`.
3. Доказать, что система функционирует в режиме `SINGLE_ACTIVE_CONTEXT`, где заказ 1002 вытесняет 1001, гарантируя отсутствие контаминации и исключая параллельное удержание двух состояний без платформенного пула сессий.

## 2. Фиксация GAP
- **Идентификатор:** `GAP-SC009-CONCURRENCY`
- **Статус:** `OPEN`
- **Архитектурный инвариант:** Платформа гарантирует строгую изоляцию через сброс предыдущего контекста (`SINGLE_ACTIVE_CONTEXT`).
