# ТЗ-VOICE-SC-PASS-001: Голосовое формирование заказа пассажиром с уточнениями

## 1. Назначение и Архитектурный Контракт
Сценарий доказывает способность платформы вести естественный многоходовый голосовой диалог формирования заказа такси пассажиром:
- **Zero Platform Modification:** Выполняется строго поверх уже принятых возможностей `PLATFORM-010..016`.
- **Domain-Agnostic Core:** В `src/platform/*` отсутствует любая специфическая логика заказа такси. Вся семантика (слоты, промпты, типы машин) полностью декларативна и загружается из `scenario-passenger-order.json`.
- **Zero Execution Invariant:** До получения подтверждения `confirmation = 'CONFIRMED'` счётчик исполнений `executionCount === 0`.
- **Recovery / Slot Replacement:** Изменение слота на лету (например, замена `airport` на `center`, или `comfort` на `standard`) производит замену значения в текущем контексте без создания дубликатов и без сохранения устаревших значений в итоговом payload.

---

## 2. Порядок Диалога (Канонический сценарий)
1. **Шаг 1 (Инициация):** `«Мне нужно в аэропорт»` $\to$ Intent: `CREATE_TAXI_ORDER`, `destination: 'airport'`. Промпт: `«Откуда вас забрать?»`. (Executions: 0)
2. **Шаг 2 (Pickup):** `«Отсюда»` $\to$ `pickup: 'CURRENT_LOCATION'`. Промпт: `«Сколько пассажиров?»`. (Executions: 0)
3. **Шаг 3 (Пассажиры):** `«Трое»` $\to$ `passengerCount: '3'`. Промпт: `«Доступны обычное такси и комфорт. Что выбрать?»`. (Executions: 0)
4. **Шаг 4 (Класс авто):** `«Комфорт»` $\to$ `vehicleType: 'comfort'`. Промпт: `«Заказать поездку?»`. (Executions: 0)
5. **Шаг 5 (Подтверждение):** `«Да»` $\to$ `confirmation: 'CONFIRMED'`. Logical Execution $\to$ 1 (Exactly once).
